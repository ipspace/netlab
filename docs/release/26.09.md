(release-26.09)=
## New Functionality

* The [**services** module](module-services) supports [syslog clients](services-syslog-parameters) in addition to DNS clients: Arista EOS, ArubaCX, Cisco IOS, Cisco IOS XR, Cisco Nexus OS, Junos, Mikrotik RouterOS7, Nokia SR Linux, Nokia SR OS, OpenBSD, and VyOS nodes can send syslog messages to a syslog server running on a dnsmasq node. DNS clients are now also available on ArubaCX, Cisco IOS XR, Cisco Nexus OS, Junos, Mikrotik RouterOS7, Nokia SR Linux, OpenBSD, and VyOS nodes.
* Cisco IOS XRd vRouter containers are fully supported ([details](build-iosxr-clab)).
* The new **netmiko** [device configuration mode](platform-config-mode) configures virtual machines (Arista vEOS, Cisco IOS-based devices, FRRouting VMs) with the *netmiko* library over SSH instead of with Ansible modules.
* [ACL rules](generic-routing-acl) and [routing.prefix lists](generic-routing-prefix-set) accept *generic prefix sets*: IPv4/IPv6 addresses and prefixes, named prefixes, VLAN prefixes, address pools, link prefixes, or sets of prefixes from links with a specified role.
* Debugging can be enabled with the `NETLAB_DEBUG` environment variable instead of the `--debug` CLI argument ([details](dev-debug)).

**Minor improvements**

* [netlab status](netlab-status) displays memory usage per node and per lab.
* Linux, FRR, and Cumulus nodes use L4 hashing for ECMP load balancing.
* *netlab* detects containerlab-reserved node names.
* MLAG peer-links are rejected on ESI-LAG-only devices.
* **[netlab test](netlab-test)** handles user interrupts (Ctrl-C) without crashing.
* [Plugin hooks](dev-plugin-hooks) can be defined at a late transformation stage.
* `log.error()` and `log.warning()` accept a `doc_url` parameter that links the error or warning message to relevant documentation.
* Validation test specs support parent devices, template devices, and custom data types in `_keytype` validation.
* The [check.config plugin](plugin-check-config) considers files created by configlets.
* [netlab install boxes](netlab-install) uses the official procedure to create the HashiCorp repository.
* FRR release bumped to 10.7.1; SR Linux release bumped to 26.7.2.

(release-26.09-device-fixes)=
## Fixes in Configuration Templates

* IS-IS configuration templates use the **isis.metric** attribute; **isis.cost** is normalized into it.
* The **routing.acl.in**/**routing.acl.out** attributes are link attributes and can be used on links and interfaces, VLAN definitions, or nodes.
* DNS client configuration works on KinD-based and file-based container links (the `/etc/resolv.conf` file is mapped into containers by device quirks only when custom DNS servers are configured).

Arista EOS:
* OSPF and IS-IS SR-MPLS label ranges can overlap

Cisco IOS:
* EVPN transport triggers a warning
* RIPng parser is no longer confused by BGP output
* IOSvL2 does not use DNS views

Cisco IOS (with **dns.transport_vrf**):
* Uses the `dns view` command

Cisco IOS XR:
* OSPFv2/v3 adjacency logging
* XRd vRouter SSH retry timers adjusted

Cisco Nexus OS:
* OSPFv2/v3 adjacency logging
* CDP is disabled globally with the `no cdp enable` command

Junos:
* DNS client is not configured in a VRF

Linux:
* The `node_config` initial-configuration script works with the *services* module
* DNS clients work on KinD nodes

(release-26.09-breaking)=
## Breaking changes

* We're [sunsetting the **libvirt** provider](libvirt-sunset). It will remain part of _netlab_, and we'll fix eventual bugs, but it won't get new features, and we won't run device integration tests with it. Moving forward, we're focusing exclusively on the *containerlab* (**clab**) provider.
* Cisco IOSv has been [deprecated](caveats-iosv): its support level is now 'minimal', and its ancient SSH implementation is described in the caveats. If you rely on IOSv, consider migrating to another Cisco IOS-based platform.

* `bgp.remove_private_as` is always processed as a dictionary
* `netlab create` honors the `.cfg` config file suffix request and validates the topology download timeout and scheme (#3856, #3767)
* Thread lock around *containerlab* config printouts (#3777)
* Multiserver VXLAN links generate valid *containerlab* configuration (#3830)
* *libvirt* checks access to the system QEMU socket (#3877)
* *libvirt* uses `kvm-ok` from the PATH or `/usr/sbin` (#3860)
* The `Cisco IOS XRd vRouter` configuration no longer contains bogus nested `group_vars`
* Netmiko sessions switch to 'enable' mode after session establishment
* `_node_config` is considered when generating the configuration script shebang (#3824)
* The package name is displayed with the error raised from `__init__` (#3823)
* Network services feature check is performed only when needed (#3814)
* Podman node memory and status information is correct (#3804)
