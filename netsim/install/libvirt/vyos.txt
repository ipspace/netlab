Customizing VyOS for Vagrant
============================

The build VM is customized for Vagrant automatically with a NoCloud cloud-init
sequence delivered as a cidata ISO image (the bootstrap.iso attached as a
CD-ROM during the second stage).

* The VM boots from the VyOS disk image created in the first stage
* cloud-init installs the first-boot script
  (netsim/install/libvirt/vyos/user-data) as
  `/opt/vyatta/etc/config/scripts/vyos-preconfig-bootup.script`
* When the script is in place, cloud-init powers the VM off

When the packaged box boots in a lab, VyOS runs that persistent preconfig
script after initial interface name resolution but before interface rescan and
before the boot configuration is loaded. The script finds the netlab management
interface by its `ca:fe:*` MAC address and deterministic netlab data interfaces
by their `ca:f0:*` MAC addresses, writes matching `hw-id` bindings into the boot
configuration, marks itself done, and triggers a reboot. On the next boot, VyOS
uses those saved `hw-id` bindings to rename the interfaces before loading the
configuration.

The box must not contain an `eth0` configuration node. Keeping `eth0` without
`hw-id` makes VyOS treat it as a pending hardware binding; when a lab VM has
multiple NICs, VyOS refuses to guess which NIC should inherit the `eth0`
configuration and the boot fails. If you are reusing a disk from an earlier
failed attempt, recreate the base qcow2 image before continuing.
